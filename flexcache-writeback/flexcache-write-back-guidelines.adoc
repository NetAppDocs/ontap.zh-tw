= ONTAP FlexCache 回寫準則
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
FlexCache寫回涉及來源伺服器和快取伺服器之間的許多複雜互動。為了獲得最佳效能，您應該確保您的環境遵循以下準則。這些指南是基於內容創建時可用的最新主要ONTAP版本（ONTAP 9.17.1）。

最佳實務做法是在非正式作業環境中測試您的正式作業工作負載。如果您在這些準則之外實作 FlexCache 回寫，這就更重要了。

以下準則已在 NetApp 內部經過充分測試。建議您留在這些範圍內。否則可能會發生非預期的行為。

* ONTAP 9.17.1P1 引進了對FlexCache回寫功能的重大增強。強烈建議您在來源叢集和快取叢集上，在 9.17.1P1 版本之後運行目前建議版本。如果您無法執行 9.17.1 程式碼線，建議使用最新的 P 版本 9.16.1。ONTAP 9.15.1 尚未包含FlexCache回寫所需的全部修復和改進，因此不建議用於生產工作負載。
* ONTAP 9.19.1 GA、9.18.1P2、9.17.1P3、9.16.1P10 以及各個版本系列中較新的 P 版本，皆支援多元件 FlexCache 回寫快取。對於較早的 ONTAP 版本，您必須為整個 FlexCache Volume 使用單一元件。在較早版本上的多元件 FlexCaches 可能會導致資料從快取中被意外移除。
* 測試針對小於 100GB 的檔案進行，快取和來源之間的 WAN 往返時間不超過 200ms。超出這些限制的任何工作負載都可能導致意想不到的效能特性。
* 寫入 SMB 替代資料串流會導致主檔案被從快取中移出。主檔案的所有髒資料都必須先清除至來源，才能在該檔案上執行任何其他作業。替代資料串流也會轉送至來源。
* 重新命名檔案會使檔案從快取中移出。檔案的所有髒資料都必須先清除至來源，才能在該檔案上執行任何其他作業。
* 目前，唯一可在啟用回寫的 FlexCache 磁碟區上變更或設定的屬性為：
+
** 時間戳記
** 模式位元
** NT ACL
** 擁有者
** 群組
** 尺寸
+
任何其他變更或設定的屬性都會轉寄至原始伺服器，這可能會導致檔案從快取中移除。如果您需要在快取中變更或設定其他屬性，請要求您的帳戶團隊開啟 PVR 。



* 在來源處拍攝的快照會叫出與來源磁碟區相關聯的每個啟用回寫快取中所有未處理的髒資料。如果有大量的回寫活動正在進行中，這可能需要多次重試作業，因為這些髒檔案的移轉可能需要一些時間。
* 啟用回寫功能的FlexCache磁碟區不支援 SMB 機會鎖（Oplocks）寫入。
* 當來源 Volume 的可用空間降至 20% 或以下時，回寫快取會自動交換器至環繞寫入模式。這有助於防止來源空間耗盡，從而避免在啟用回寫功能的快取中留下孤立的髒資料。如果來源 Volume 過度配置，則其邏輯配置大小會大於彙總中的可用空間。20% 的臨界值是根據來源 Volume 的可用空間和彙總的可用實體容量進行評估。 `percent-used` 和  `capacity` 在可用空間已低於該臨界值時，仍可能顯示為 0%。
+
以下範例是過度配置的來源 Volume。幾乎沒有資料寫入，但彙總無法支援完整的邏輯大小：

+
[source, cli]
----
ORIGIN::> vol show -volume origin_volume -fields percent-used,available,size
vserver             volume           size    available percent-used
------------------- ---------------- ------- --------- ------------
origin_svm          origin_volume    19.70TB 1.33TB    0%
----
+
請注意 `percent-used` 為 0%，但可用空間為 19.70TB 中的 1.33TB，即 1.33 / 19.70，約有 7% 可用。這已低於 20% 的臨界值，因此該來源的回寫快取會切換至環繞寫入模式。

+
[source, cli]
----
ORIGIN::> df -h origin_volume
Filesystem               total       used      avail   capacity  Mounted on       Vserver
/vol/origin_volume/      18TB        515MB     1363GB         0%    ---           origin_svm

2 entries were displayed.
----
+
請注意， `capacity` 也為 0%，僅使用了 515MB。可用空間為 18TB 中的 1363GB，約佔檔案系統的 7%。百分比列顯示儲存的資料非常少。它們不會顯示彙總實際可提供的 Volume 大小。

* 低頻寬和 / 或容易遺失封包的叢集間網路會對 FlexCache® 寫回效能產生顯著的負面影響。雖然沒有特定的頻寬要求（因為它高度取決於您的工作負載），但 *_強烈_* 建議您確保快取與來源之間的叢集間連結健全狀況。如果您的網路容易發生封包遺失，且您執行的是 ONTAP 9.19.1 或更新版本，請考慮使用 link:../networking/improve-tcp-wan-performance.html["TCP RACK"] 來提升效能。
