= 了解搭配 ONTAP 系統設定 FC 架構的最佳實務
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
遵循 FC 架構組態最佳實踐，可提高主機和目標在架構變更期間的效能、可靠性和穩定性。

.建議的 FC 架構組態最佳實務
* *單一啟動器 / 單一目標（SI/ST）分區*
+
SI/ST 分區可降低架構變更期間的延遲峰值，消除串擾，限制註冊狀態變更通知（RSCNs），簡化疑難排解，並將路徑計數保持在主機限制範圍內。

+
** 主機影響：SI/ST 分區可確保可預測的 MPIO 行為、更快速的探索，以及更少的 All Path Down （APD）/Permanent Device Loss （PDL） 事件。
** 目標影響：SI/ST 分區可確保較少的登入/登出事件，以及穩定的 FC 工作階段。


* *基於目標 LIF WWPN（而非實體連接埠）的 WWPN 分區*
+
以 WWPN 為基礎的分區可實現 LIF 移動性、接管/歸還、無需重新分區的不中斷營運，並防止在維護期間重設路徑。

+
** 主機影響：基於 WWPN 的分區可確保在 LIF 移動或控制器容錯移轉期間不會出現路徑遺失。
** 目標影響：基於 WWPN 的分區確保 ONTAP 可以透明地移動目標 LIF。


* *所有 FC 交換器均已啟用 NPIV*
+
連接到架構的所有交換器都必須支援 NPIV，並且必須啟用 NPIV。ONTAP 使用 N_Port ID 虛擬化（NPIV）來呈現 FC 目標。如果沒有它，目標 LIF 將無法正確登入。

+
** 主機影響：NPIV 可防止間歇性路徑中斷和裝置遺失。
** 目標影響：NPIV 確保目標 LIF 可見度和穩定的 FC 登入。


* *完全隔離的雙重獨立架構*
+
雙獨立架構由兩個分隔的實體交換器、電源和線材組成。架構 A 和架構 B 互不連接。它們各自維護自己的 FC 名稱伺服器、區域集和網域 ID。由於這些架構是完全隔離的，因此不存在單點故障。可以在其中一個架構上執行不中斷維護，而另一個架構則繼續運作。

+
** 主機影響：雙獨立架構支援在架構韌體升級或故障期間持續進行 I/O。
** 目標影響：雙獨立架構在交換器出現問題時保持備援目標存取。


* *固定 FC 埠速度（避免自動協商）*
+
自動協商可能會延遲架構重建，導致速度不匹配，並商機重新收斂延遲和連結抖動。

+
** 主機影響：固定 FC 連接埠速度可縮短連結重置期間的停電視窗。
** 目標影響：固定 FC 連接埠速度可在節點或交換器事件發生後更快啟動連接埠。


* *嚴格遵守 NetApp 互通性矩陣工具（IMT）驗證的組態（HBA、驅動程式、韌體、交換器）*
+
嚴格遵守在 https://mysupport.netapp.com/matrix["NetApp IMT"^]中驗證的組態，可維持預期的延遲和處理量。

+
** 主機影響：使用 IMT 驗證的組態可避免無法解釋的 I/O 錯誤和逾時。
** 目標影響：使用 IMT 驗證的組態可防止協定層級不相容。


* *主動監控 FC 錯誤計數器（CRC、同步遺失、RECV_ERROR）*
+
在 ONTAP 儲存設備計數器偵測到它們之前，架構錯誤通常會表現為主機端延遲或 I/O 錯誤。主動監控 FC 錯誤計數可防止延遲持續增加。

+
** 主機影響：主動監控能夠及早發現問題，防止主機 I/O 重試和應用程式停滯。
** 目標影響：主動監控可避免將架構問題誤認為儲存設備問題。


* *避免 SAN 流量的交換器間連結（ISL）超額訂閱*
+
壅塞的 ISL 會導致信用匱乏和慢速耗盡行為。

+
** 主機影響：避免 ISL 超額訂閱可減少主機 I/O 等待時間和排隊狀況。
** 目標影響：避免 ISL 超額訂閱可防止對 ONTAP FC 連接埠造成反壓力。
