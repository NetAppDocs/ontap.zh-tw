= 設定 ONTAP ARP/AI 快照回應原則和設定
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
從 ONTAP 9.16.1 開始，您可以使用 CLI 控制 AI 自主勒索軟體防護（ARP/AI）快照的建立和保留設定。從 ONTAP 9.20.1 開始，您也可以設定定期快照和攻擊快照的回應原則，以控制 ARP/AI 在偵測到異常活動時是否建立快照。


NOTE: 如果您執行的是 ONTAP 9.15.1 或更早版本，請參閱link:modify-snapshot-options-arp.html["調整自動產生的 ARP 快照的設置"]。



[[configure-a-snapshot-response-policy]]
== 設定快照回應原則

從 ONTAP 9.20.1 開始，您可以針對週期性和攻擊快照設定 ARP/AI 快照回應原則，以控制 ARP/AI 在偵測到異常活動時是否建立快照。您可以在 SVM 層級設定此原則（SVM 上的所有 Volume 都將繼承此設定），也可以在 Volume 層級置換此原則。

可使用下列快照回應原則：

[cols="1,3"]
|===
| 原則 | 行為 


| `alert-with-proactive-and-periodic-snapshot` | （預設）ARP/AI 產生警報和事件日誌，定期建立快照，並在偵測到攻擊時建立額外的快照。 


| `alert-with-proactive-snapshot` | ARP/AI 僅在偵測到攻擊時產生警報和事件日誌並建立快照。不會建立定期快照。 


| `alert-only` | ARP/AI 僅產生警示與事件記錄。不會建立 ARP/AI 快照。 
|===

CAUTION: 如果您將原則設為 `alert-only`，ARP/AI 將不會建立快照。如果確認發生勒索軟體攻擊，即使在作用中的攻擊期間，也沒有可用於資料恢復的 ARP/AI 快照。在使用 `alert-only`之前，請確保您有足夠的外部資料保護，例如排程的 ONTAP 快照、SnapCenter 備份或其他備份解決方案。


NOTE: 當您變更快照回應原則時，現有的 ARP/AI 快照不會立即刪除。它們會在達到排定的到期時間時被刪除。請勿期望在原則變更後立即回收儲存容量。

[role="tabbed-block"]
====
.系統管理員
--
*在 SVM 層級設定快照回應原則：*

. 選擇 *叢集* > *儲存 VM*，然後選擇儲存 VM。
. 導覽至 *設定* 索引標籤。在 *安全性* 下，找到 *防勒索軟體* 方塊並選取 image:icon_pencil.gif["編輯圖示"]。
. 在 *保護層級* 下，選擇要套用於 SVM 上所有啟用 ARP/AI 的 Volume 的保護類型。
. 選擇*保存*。


*在 Volume 層級設定快照回應原則：*

. 選擇 *儲存設備* > *Volume*，然後選擇 Volume。
. 在 *安全性* 標籤中，找到 *反勒索軟體* 區段並選取 image:icon_pencil.gif["編輯圖示"]。
. 在 *保護層級* 下，選擇快照回應原則以置換此 Volume 的 SVM 層級設定。
. 選擇*保存*。


--
.CLI
--
. 顯示目前 ARP/AI 快照回應原則：
+
在 SVM 層級：

+
[source, cli]
----
security anti-ransomware vserver snapshot-settings show -vserver <svm_name>
----
+
在 Volume 層級：

+
[source, cli]
----
security anti-ransomware volume snapshot-settings show -vserver <svm_name> -volume <volume_name>
----
. 設定 ARP/AI 快照回應原則：
+
在 SVM 層級：

+
[source, cli]
----
security anti-ransomware vserver snapshot-settings modify -vserver <svm_name> -anti-ransomware-snapshot-policy <policy>
----
+

NOTE: 此設定適用於已啟用 ARP/AI 的 Volume。它不會追溯影響現有已啟用 ARP/AI 的 Volume。

+
在 Volume 層級（置換 SVM 層級設定）：

+
[source, cli]
----
security anti-ransomware volume snapshot-settings modify -vserver <svm_name> -volume <volume_name> -anti-ransomware-snapshot-policy <policy>
----


--

[[adjust-snapshot-creation-and-retention-settings]]
== 調整快照建立和保留設定


NOTE: 從 ONTAP 9.20.1 開始，以下設定僅在快照回應原則為 `alert-with-proactive-snapshot`或 `alert-with-proactive-and-periodic-snapshot`時適用。

.開始之前
您只能修改 link:../system-admin/types-svms-concept.html["節點SVM"] 的 ARP/AI 快照選項，而不能修改其他類型的 SVM 的 ARP/AI 快照選項。

.步驟
. 顯示所有目前的 ARP/AI 快照設定：
+
[source, cli]
----
options -option-name arw*
----
. 顯示選定的目前 ARP/AI 快照設定：
+
[source, cli]
----
options -option-name <arw_setting_name>
----
. 修改 ARP/AI 快照設定：
+
[source, cli]
----
options -option-name <arw_setting_name> -option-value <arw_setting_value>
----
+
您可以修改以下設定（ONTAP 9.16.1 及更新版本）：

+
[cols="1,3,1"]
|===
| 設定 | 說明 | 支援 ARP/AI 的版本 


| `arw.snap.max.count`  a| 
指定 Volume 中任何時間點可同時存在的 ARP/AI 快照最大數量。較舊的複本將被刪除，以確保 ARP/AI 快照的總數保持在此限制範圍內。


NOTE: 從 ONTAP 9.20.1 開始，此設定僅在快照回應原則設定為 `alert-with-proactive-and-periodic-snapshot`時生效。當原則設定為 `alert-with-proactive-snapshot`或 `alert-only`時， ONTAP 將忽略此設定。
 a| 
ONTAP 9.16.1 及更新版本



| `arw.snap.create.interval.hours`  a| 
指定 ARP/AI 快照之間的間隔時間（以小時為單位）。當懷疑存在基於資料熵的攻擊，且最近建立的快照早於指定的間隔時間時，將建立新的 ARP/AI 快照。
 a| 
ONTAP 9.16.1 及更新版本



| `arw.snap.normal.retain.interval.hours`  a| 
指定 ARP/AI 快照的保留時長（以小時為單位）。當 ARP/AI 快照達到保留期間臨界值時，即會被刪除。
 a| 
ONTAP 9.16.1（已在 9.17.1 及更新版本中棄用）



| `arw.snap.max.retain.interval.days`  a| 
指定 ARP/AI 快照可保留的最大天數。當 Volume 上未報告任何攻擊時，早於此期限的 ARP/AI 快照將會被刪除。


NOTE: 如果 ARP/AI 偵測到威脅，則會忽略最大保留間隔。為回應威脅而建立的 ARP/AI 快照將保留，直到您對該威脅做出回應。當您將威脅標記為誤報時， `arw.snap.retain.hours.after.clear.suspect.false.alert` 所指定的保留定時器將套用至 ARP/AI 快照。定時器到期後，將恢復標準保留設定。
 a| 
ONTAP 9.16.1（已在 9.17.1 及更新版本中棄用）



| `arw.snap.create.interval.hours.post.max.count`  a| 
指定當 Volume 已包含最大數量的 ARP/AI 快照時，ARP/AI 快照之間的間隔（以小時為單位）。達到最大數量後，將刪除一個 ARP/AI 快照，以便為新複本騰出空間。使用此選項可降低建立速度，以保留較舊的複本。
 a| 
ONTAP 9.16.1（已在 9.17.1 及更新版本中棄用）



| `arw.snap.new.extns.interval.hours`  a| 
指定偵測到新檔案副檔名時所建立的 ARP/AI 快照之間的間隔（以小時為單位）。當偵測到新檔案副檔名且上一次此類快照的建立時間早於指定的間隔時，系統會建立一個新的 ARP/AI 快照。此選項獨立於 `arw.snap.create.interval.hours`之外，後者用於指定基於熵的快照間隔。
 a| 
ONTAP 9.16.1（已在 9.17.1 及更新版本中棄用）



| `arw.snap.low.encryption.retain.duration.hours`  a| 
指定在低加密活動期間建立的 ARP/AI 快照的保留期間（以小時為單位）。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.snap.retain.hours.after.clear.suspect.false.alert`  a| 
指定在系統管理員將攻擊事件標記為誤報後，作為預防措施保留 ARP/AI 快照的間隔（以小時為單位）。
 a| 
ONTAP 9.16.1 及更新版本



| `arw.snap.retain.hours.after.clear.suspect.real.attack`  a| 
指定在系統管理員將攻擊事件標記為真實攻擊後，作為預防措施保留 ARP/AI 快照的間隔（以小時為單位）。
 a| 
ONTAP 9.16.1 及更新版本



| `arw.snap.surge.interval.days`  a| 
指定回應 IO 激增而建立的 ARP/AI 快照之間的間隔（以天為單位）。此選項也指定 ARP/AI 激增快照的保留期間（以天為單位）。
 a| 
ONTAP 9.16.1 及更新版本



| `arw.high.encryption.alert.enabled`  a| 
啟用高加密等級警報。當設定為 `on`（預設值）時，當加密百分比超過 `arw.high.encryption.percentage.threshold`中指定的臨界值時，ONTAP 會發出警報。
 a| 
僅限 ONTAP 9.17.1



| `arw.high.encryption.percentage.threshold`  a| 
指定 Volume 的最大加密百分比。如果加密百分比超過此臨界值，ONTAP 會將此增加視為攻擊並建立 ARP/AI 快照。 `arw.high.encryption.alert.enabled`必須設為 `on`才能使此選項生效。
 a| 
僅限 ONTAP 9.17.1



| `arw.snap.high.encryption.retain.duration.hours`  a| 
指定在高加密閾值事件期間建立的快照的保留持續時間間隔（以小時為單位）。
 a| 
ONTAP 9.17.1 及更高版本

|===
. 如果您在 SAN 環境中使用 ARP/AI，也可以修改以下評估期設定：
+
[cols="1,3,1"]
|===
| 設定 | 說明 | 支援的版本 


| `arw.block_device.auto.learn.threshold.min_value`  a| 
指定區塊設備評估的自動學習階段的最小加密閾值百分比值。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.auto.learn.threshold.max_value`  a| 
指定區塊設備評估的自動學習階段的最大加密閾值百分比值。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.evaluation.phase.min_hours`  a| 
指定在設定加密閾值之前評估階段必須運行的最小間隔（以小時為單位）。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.evaluation.phase.max_hours`  a| 
指定在設定加密閾值之前評估階段必須運行的最大間隔（以小時為單位）。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.evaluation.phase.min_data_ingest_size_GB`  a| 
指定在設定加密閾值之前評估階段必須提取的最小資料量（以 GB 為單位）。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.evaluation.phase.alert.enabled`  a| 
指定是否為區塊設備上的 ARP/AI 評估階段啟用警報。預設值為 `True`。
 a| 
ONTAP 9.17.1 及更高版本



| `arw.block_device.evaluation.phase.alert.threshold`  a| 
指定在區塊裝置上進行 ARP/AI 評估階段的臨界值百分比。如果加密百分比超過此臨界值，則會觸發警報。
 a| 
ONTAP 9.17.1 及更高版本

|===
