[[data-protection]]
== 資料保護

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirror 雲端支援原地還原至原始來源 Volume]
 a| 
SnapMirror 雲端支援 FlexVol Volume 的原地還原作業，讓您能夠直接將雲端快照還原至原始來源 Volume。ONTAP 會選擇最新的通用快照並執行遞增傳輸，進而縮短還原時間。



 a| 
xref:../snapmirror-active-sync/limits-reference.html[提高 SnapMirror 作用中同步物件限制]
 a| 
SnapMirror 作用中同步將每個 HA 配對支援的 Volume 數量增加至 600（適用於 SAN 和 NAS 設定）。



 a| 
xref:../snaplock/snapshot-lock-concept.html[搭配 SnapMirror 作用中同步 NAS 的防篡改快照支援]
 a| 
ONTAP 新增了對使用 SnapMirror 作用中同步 NAS FlexVol Volume 的防篡改快照支援。此增強功能可讓客戶將 SnapMirror 作用中同步 NAS 可用度與不可變的快照保護結合。



 a| 
xref:../data-protection/modify-svm-dr-dest-vol-capacity-task.html[增強型 SVM 災難恢復]
 a| 
ONTAP 透過允許使用標準管理員權限 Volume 修改工作流程，在 SVM-DR 目的地 Volume 上修改選定的 Volume 屬性，來增強 SVM 災難恢復，進而減少對支援協助程序的需求。

ONTAP 也將選擇加入的 SVM-DR 快速重新同步支援擴展至 FlexGroup 成員，協助承載 FlexGroup 的大型 SVM 在 DR 演練、重新同步或翻轉重新同步工作流程後，更快恢復到受保護狀態。

如需詳細資訊，請參閱 xref:../data-protection/resync-svm-destination-task.html[重新同步 ONTAP SnapMirror 目的地 SVM 上的資料]。



 a| 
xref:../data-protection/configure-backend-fc-replication.html[後端支援 SnapMirror 透過 FC 進行複寫]
 a| 
您可以透過現有的 Fibre Channel (FC) 架構設定後端 SnapMirror 非同步複寫與 SnapLock for SnapVault。

這使得複寫流量能夠完全在現有的 SAN 基礎架構內傳輸。在 ONTAP 9.20.1 之前的版本中，這些複寫關係的流量完全透過叢集間 IP 網路傳輸。



 a| 
xref:../consistency-groups/protect-task.html[從非 SnapLock 來源一致性群組複寫至 SnapLock for SnapVault 目的地一致性群組]
 a| 
您可以從非 SnapLock 來源一致性群組複寫至 SnapLock for SnapVault 目的地一致性群組。SnapLock for SnapVault 可保護複寫的一致性群組免於意外或惡意刪除。



 a| 
xref:../san-admin/fc-sp-3-security-support.html[使用 Broadcom 安全的 HBA 進行 FC-SP-3 驗證和加密]
 a| 
ONTAP 支援在搭配 AFF 與 FAS 系統的 Broadcom 安全 HBA 上使用 Fibre Channel 安全傳輸協定 3 （FC-SP-3） 驗證與加密。FC-SP-3 支援可實現硬體層級的端對端加密與裝置驗證，以保護 FC 與 NVMe/FC SAN 主機和 ONTAP 儲存系統之間傳輸的資料，同時符合 T11 Fibre Channel 安全性標準。

加密已卸載，因此不會對您的儲存系統造成效能影響。

[[fpolicy-enhancements]]
== FPolicy 增強功能

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-nfsv4-concept.html[FPolicy 對 NFS 4.2 的支援]
 a| 
FPolicy 將檔案存取監控擴展到 NFSv4.2，從而為使用最新 NFS 傳輸協定版本的環境提供稽核、法規遵循和網路彈性工作流程。FPolicy 會為 NFSv4.2 檔案作業產生通知，包括擴充屬性寫入（SETXATTR、REMOVEXATTR）以及透過 SETATTR/GETATTR 進行的安全性標籤變更。NFSv4.2 通知需要設定為 protobuf 格式的外部引擎。



 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-s3.html[Fpolicy 對 S3 物件儲存的支援]
 a| 
FPolicy 為 S3 物件工作流程提供安全性監控。這為檔案和物件儲存提供統一的 FPolicy 架構，簡化混合資料環境的安全性操作。FPolicy for S3 物件提供物件生命週期可見度，以監控物件建立、刪除和中繼資料標籤變更，滿足安全性、法規遵循和稽核要求。此功能提供無中斷監控，不會影響效能。

[[nas]]
== NAS

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
xref:../smb-admin/supported-versions-functionality-concept.html[Windows 用戶端的 SMB 規範化名稱查詢支援]
 a| 
Windows 用戶端只需單一要求即可擷取規範的檔案和目錄名稱，從而降低檔案開啟延遲，並提高企業桌面、應用程式和檔案伺服器的 SMB 相容性。ONTAP 自動傳回開啟檔案和目錄的規範路徑，無需額外組態即可避免在 Windows 11 24H2 及更新版本的用戶端上進行逐一元件的查閱。



 a| 
xref:../nfs-admin/support-vmware-vstorage-over-nfs-concept.html[VMware NFS 資料儲存的自動空間回收]
 a| 
ONTAP 透過適用於 VMware VAAI 的 NetApp NFS 外掛程式支援 NFS 資料儲存的自動空間回收。這有助於在 VMware ESXi 9.0 或更新版本的主機發出 UNMAP 作業時，從精簡配置的 VMDK 區塊範圍中回收空間。



 a| 
xref:../volumes/cautions-increasing-maximum-directory-size-concept.html[ONTAP FlexVol 磁碟區的最大目錄大小]
 a| 
ONTAP 透過支援高達 4GB 的目錄大小，提升了包含多達約 2500 萬個檔案之超大型目錄的效能。執行在單一目錄中產生極高檔案數量之工作負載（例如 AI 訓練）的客戶，可享有避免以往大型目錄所造成之效能損失的優點。它還能確保目錄在資料保護容錯移轉後仍保持完整索引，藉此提高彈性，因此即使 SnapMirror 關係中斷，複寫的複本也能發揮良好的效能。此功能適用於 AFF 和 FAS 儲存系統，包括 MetroCluster 部署；可視需要為每個 Volume 啟用。



 a| 
xref:../task_nas_provide_client_access_with_name_services.html[自動 SID 到 UNIX ID 轉換支援]
 a| 
ONTAP 為 LDAP 連接的 SVM 引入了自動 SID 到 UNIX ID 轉換支援，可根據 Windows SID 產生和反轉 POSIX UID/GID。這消除了在 Active Directory 中手動維護 uidNumber / gidNumber 屬性的需要，從而降低了管理成本，並有助於確保 NFS 和 SMB 之間一致的檔案存取。這項符合業界標準的功能對於正在將大型網路從基於 SSSD 的 NAS 平台移轉並希望保持身分對應一致性的客戶尤其重要。此功能預設為停用，需針對每個 SVM 進行設定。

[[san]]
== SAN

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
xref:../revert/remove-persistent-reservation-registrations.html[增加 SCSI 持續保留註冊規模]
 a| 
每個 LUN 支援的最大 SCSI-3 持續保留註冊數從 182 增加到 256。這有助於較大的叢集 SAN 環境（例如 VMware 客體叢集和 Windows Server 容錯移轉叢集）在共享的 LUN 上支援更多主機註冊，而無需變更持續保留管理工作流程。



 a| 
SAN 複本卸載效能提升
 a| 
ONTAP 可提升符合條件的 NVMe 和 SCSI 複本工作負載的 SAN 複本卸載效能。詳情請聯絡您的 NetApp 代表。



 a| 
xref:../svm-migrate/migrate-svm-task.html[支援將儲存設備虛擬機器從 ASA r2 系統無中斷移轉到 ASA 或 AFF 系統]
 a| 
您可以將儲存設備虛擬機器（SVM）從 2 節點 ASA r2 叢集無中斷地移轉到 2 節點 ASA 叢集或 2 節點 AFF 叢集。在移轉過程中，現有的主機對映以及 LUN 和命名空間的儲存設備單元組態將保持不變，從而降低維運工作量和風險。

== S3 物件儲存

[cols="30%,70%"]
|===

xref:../s3-snapmirror/index.html#snapmirror-s3-requirements[MetroCluster 支援 SnapMirror S3]
 a| 
您可以在 MetroCluster 組態中建立 SnapMirror S3 關係，這些關係在切換和切回過程中可從作用中站台持續保持可用並恢復運作。



 a| 
xref:../s3-config/create-bucket-lifecycle-rule-task.html[MetroCluster 支援 ONTAP S3 儲存桶生命週期管理]

您可以在 MetroCluster 組態中為原生 S3 儲存桶建立 ONTAP S3 儲存桶生命週期管理規則。

xref:../s3-config/create-s3-object-store-server-task.html[靈活的 S3 儲存桶規模]

 a| 
xref:../s3-multiprotocol/create-nas-bucket-task.html[適用於 FlexCache Volume 上 NAS 儲存桶的 S3 伺服器端複本支援]

FlexCache Volume 上的 S3 NAS 儲存桶支援使用 S3 CopyObject 和 UploadPartCopy API 進行伺服器端物件複本操作。您可以在同一個 FlexCache NAS 儲存桶內複製物件，或是將物件從由 FlexGroup Volume 支援的 S3 NAS 儲存桶複製到 FlexCache NAS 儲存桶。



 a| 
xref:../s3-config/ontap-s3-supported-actions-reference.html[ONTAP S3 靈活 Checksum 支援]
 a| 
ONTAP S3 支援與 AWS 相容的 CRC-64NVME Checksum，用於 S3 NAS 儲存桶。當 S3 用戶端為支援的上傳和多部分作業提供 Checksum 資訊時，ONTAP 會驗證並儲存 Checksum，並為支援的 GET 和 HEAD 要求傳回 Checksum 資訊。

[[security]]
== 安全性

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
用於管理連線泛洪與預叢集增強功能的 Apache 公平佇列
 a| 
ONTAP 在管理 Web 伺服器上引進了選擇加入、預設關閉的來源 IP 公平佇列機制，以協助在管理連線激增期間維持對 REST、System Manager 及 ONTAPI 的存取。ONTAP 也支援透過僅限預先叢集的 REST API 進行映像安裝，並增強動態主機設定協定（DHCP）的處理，確保在節點等待叢集設定期間，預先叢集節點管理 LIF 能夠在租約續約與 IP 位址變更時保持可用。



 a| 
xref:../anti-ransomware/modify-snapshot-options-arpai.html[增強對 ARP/AI 快照回應原則的控制]
 a| 
您可以在 SVM 或 Volume 層級設定 ARP/AI 快照回應原則，以控制 ARP/AI 在偵測到異常活動時是否建立快照。有三種原則可供選擇： `alert-with-proactive-and-periodic-snapshot` （預設，保留現有行為）、 `alert-with-proactive-snapshot` （僅攻擊快照，無定期快照），以及 `alert-only` （僅警示與事件記錄，不建立快照）。升級至 9.20.1 後，預設的定期快照最大數量將從 6 變更為 2，預設保留期間將從 12 小時變更為 7 小時，除非先前已修改過這些節點層級選項。



 a| 
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[資料 SVM 的金鑰管理工作流程改進]
 a| 
在資料 SVM 上啟用外部金鑰管理程式後， ONTAP 可以自動將該 SVM 的 Volume 加密金鑰從管理範圍的金鑰管理程式移轉到新的資料 SVM 金鑰管理程式。這簡化了向外部金鑰管理的轉換，並省去了標準工作流程中分隔的手冊移轉步驟。



 a| 
xref:../multi-admin-verify/index.html[支援將 IdP、AD 和 LDAP 群組作為 MAV 核准者]
 a| 
除了個別系統管理員之外，MAV 核准群組還可以包含身分供應商 (IdP)、Active Directory (AD) 和 LDAP (nsswitch) 群組作為核准者。支援的群組類型包括 Entra ID、ADFS、AD 網域群組和 LDAP 群組。在 IdP、AD 或 LDAP 目錄中新增或移除使用者，無需變更 MAV 組態。使用者群組成員資格的變更，會在使用者下次登入重新驗證後生效。您可以使用 security multi-admin-verify registered-operations show 命令，顯示目前叢集上所有受 MAV 保護的可用作業。



 a| 
xref:../networking/configure_snmpv3_users_in_a_cluster.html[支援 SNMPv3 SHA-512 驗證]
 a| 
ONTAP 支援對 SNMPv3 使用者進行 SHA-512 驗證。此增強功能可讓您對外部 SNMP 用戶端和交換器監控（包括需要 SHA-512 驗證的交換器）使用更強大的 SNMPv3 驗證。如需詳細資訊，請參閱「在 ONTAP 叢集中設定 SNMPv3 使用者」和「設定 SNMPv3 以進行乙太網路交換器健全狀況監控」。

如需詳細資訊，請參閱 https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["設定 SNMPv3 以監控乙太網路交換器的健全狀況"]。

 a| 
自動重複資料刪除技術排程器（ADS）最佳化
 a| 
ONTAP 提升了 ADS（自動重複資料刪除排程器）的效能，允許每個節點有更多並行的重複資料刪除工作階段，以及更智慧、更具針對性的節流，以進一步平衡用戶端 I/O。DP Volume（來自 SnapMirror 傳輸）上的重複資料刪除活動和全域重複資料刪除工作階段，會與一般 Volume 重複資料刪除一起代管，這可減少爭用與中繼資料成長。您無需變更組態，即可獲得儲存效率節約的優點，尤其是在混合工作負載下。此功能預設為啟用，並適用於 AFF 儲存系統。

[[storage-resource-management-enhancements]]
== 儲存資源管理增強功能

[cols="30%,70%"]
|===
| 更新 | 說明 


 a| 
xref:../s3-config/delete-recover-bucket-with-data-task.html[支援刪除包含物件的 ONTAP S3 儲存桶]
 a| 
管理員可以在使用可設定的基於保留的恢復視窗時，安排刪除包含物件的儲存桶。這可讓儲存桶在保留期到期前恢復。此功能可減少過期積壓，並使高變動率工作負載的容量能夠更快地重新利用。



 a| 
xref:../flexcache/sizing-concept.html[FlexCache 規模限制增加]
 a| 
當每個 Volume 使用一個構成要素時，支援的 FlexCache Volume 數量會增加至每個節點 2500 個，以及每個 HA 配對 5000 個。

您可以從來源 Volume 建立的 FlexCache Volume 數量增加至 200，每個來源的回寫快取數量增加至 50。



 a| 
xref:../flexcache/supported-unsupported-features-concept.html[搭配 FlexCache 的 NVFail 支援]
 a| 
您可以建立與已啟用 NVFAIL 來源的 FlexCache 關係。您也可以獨立於來源 Volume ，在快取 Volume 上啟用 NVFAIL 。在發生 NVFAIL 的來源或快取 Volume 上， ONTAP 會阻止資料讀取或修改，同時保留已修改快取資料的寫回，並在恢復後恢復正常的 I/O 。



 a| 
非同步刪除的效能增強
 a| 
ONTAP 可提升非同步刪除效能，並加快 NAS/SMB 用戶端的空間回收。詳情請聯絡您的 NetApp 代表。



 a| 
xref:../data-protection/calculate-reclaimable-space-task.html[支援計算 FlexGroup Volume 上的可回收空間]
 a| 
ONTAP 支援在刪除 FlexGroup Volume 上的快照之前重新計算可回收空間。



 a| 
xref:../flexgroup/provision-automatically-task.html[自動配置高效能 FlexGroup Volume]
 a|

 a| 
xref:../volumes/manage-svm-capacity.html[針對 ONTAP SVM 容量限制的 MetroCluster IP 支援]
 a| 
您可以為屬於 MetroCluster IP 組態的 SVM 設定儲存設備限制。



 a| 
FlexCache Volume 計量
 a| 
FlexCache Volume 計量報告 FlexCache Volume 與其來源 Volume 之間交換的資料和中繼資料量。現有的 ONTAP REST Volume 統計資料和計量端點新增了兩個屬性，可提供 FlexCache 到來源以及來源到 FlexCache 資料傳輸的可見度。這些計數器會自動收集，無需任何組態；它們有助於容量規劃、效能分析、網路疑難排解和計費分析。此功能要求在 FlexCache 和來源節點上均執行 ONTAP 9.20 或更新版本。如需詳細資訊，請參閱 link:https://docs.netapp.com/us-en/ontap-automation["ONTAP 自動化"^] 文件。



 a| 
叢集內重新平衡
 a| 
ONTAP 引入了兩項全新的 Balanced Placement 功能，協助您在工作負載和叢集容量不斷變化的情況下，以最少的管理工作量維持叢集的最佳效能。資源配置時的放置控制可讓客戶在透過 REST API 放置新 Volume 時，指出應優先考量效能或空間需求。空間效能重新平衡（SPR）是一個背景程序，會持續尋找叢集中逐漸形成的效能熱點或彙總空間壓力。根據設定的模式，SPR 會透過 EMS 通知建議進行修正性的 Volume 移動，或是使用標準且不中斷營運的 ONTAP Volume 移動作業來自動執行移動。如需詳細資訊，請參閱 link:https://docs.netapp.com/us-en/ontap-automation["ONTAP 自動化"^] 文件。
