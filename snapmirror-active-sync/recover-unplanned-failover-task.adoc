= 從自動的、計劃外的ONTAP集群故障轉移操作中恢復
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
當主要叢集停機或隔離的時，會發生自動計劃外容錯移轉 （AUFO） 作業。SnapMirror 作用中同步會偵測此類故障，並啟動自動計劃外容錯移轉至次要叢集。次要叢集將轉換為主要叢集（慣用叢集），並開始為用戶端提供服務。請注意，故障偵測和容錯移轉處理只能在 ONTAP Mediator 的協助下完成。


NOTE: 在自動非計劃性容錯移轉之後，重新掃描主機路徑非常重要，以確保不會遺失 I/O 路徑。



[[reestablish-the-protection-relationship-after-an-unplanned-failover]]
== 在非計畫性容錯移轉之後重新建立保護關係

一旦原始主要叢集（例如叢集 A）恢復，SnapMirror 作用中同步會自動建立反向保護。如果您希望還原原始狀態，使叢集 A 成為主要的慣用叢集，可以使用 System Manager 或 ONTAP CLI 啟動計劃性容錯移轉作業，以執行手動容錯回復。

[role="tabbed-block"]
====
.系統管理員
--
.步驟

IMPORTANT: 從 ONTAP 9.8 到 ONTAP 9.14.1，SnapMirror 主動同步被稱為 SnapMirror Business Continuity（SM-BC）。

. 導航至*保護>關係*並等待關係狀態顯示“InSync”。
. 若要對原始來源叢集執行故障回復並恢復作業，請按一下 image:icon_kabob.gif["功能表選項圖示"] 並選取 *Failover*。


--
.CLI
--
您可以使用監控自動非計畫性容錯移轉的狀態 `snapmirror failover show` 命令。

例如：

....
ClusterB::> snapmirror failover show -instance
Start Time: 9/23/2020 22:03:29
         Source Path: vs1:/cg/scg3
    Destination Path: vs3:/cg/dcg3
     Failover Status: completed
        Error Reason:
            End Time: 9/23/2020 22:03:30
Primary Data Cluster: cluster-2
Last Progress Update: -
       Failover Type: unplanned
  Error Reason codes: -
....
您可以在原始主要叢集上使用  `snapmirror show` 命令來監控反向保護關係的狀態。

例如：

....
ClusterA::> snapmirror show
                                                                               Progress
Source             Destination  Mirror        Relationship   Total             Last
Path         Type  Path         State         Status         Progress  Healthy Updated
-----------  ----  ------------ -------       -------------- --------- ------- --------
vs3:/cg/dcg3 XDP   vs1:/cg/scg3 Snapmirrored  InSync          -         true    -
....
您可以使用  `snapmirror failover start` 命令對原始主要叢集執行容錯回復。

例如：

....
ClusterA::> snapmirror failover start -destination-path vs1:/cg/scg3
....
請參閱 link:https://docs.netapp.com/us-en/ontap-ems-9131/smbc-aufo-events.html["EMS 參考"^] 以瞭解事件訊息及修正行動。

--

[[resume-protection-in-a-fan-out-configuration-after-failover]]
== 在容錯移轉後、恢復風扇輸出組態的保護

從 ONTAP 9.15.1 開始，SnapMirror 主動同步支援在 SAN 關係中發生故障轉移事件後自動重新設定連出連結。在 NAS 組態中，SnapMirror 主動同步故障轉移後，您必須手動重新設定保護關係。非同步連出連結可以是一致性群組關係，也可以是獨立 Volume 關係。如需詳細資訊，請參閱 link:interoperability-reference.html#fan-out-configurations["連出組態"]。

如果您使用的是 ONTAP 9.14.1 或更早版本、而且在 SnapMirror 主動同步關係中的次要叢集上發生容錯移轉、 SnapMirror 非同步目的地就會變得不正常。您必須刪除和重新建立與 SnapMirror 非同步端點的關係、以手動還原保護。

.步驟
. 確認容錯移轉已成功完成：
`snapmirror failover show`
. 在 SnapMirror 非同步端點上、刪除扇出端點：
`snapmirror delete -destination-path _destination_path_`
. 在第三個站台上、在新的 SnapMirror 主動式同步主磁碟區和非同步扇出目的地磁碟區之間建立 SnapMirror 非同步關係：
`snapmirror create -source-path _source_path_ -destination-path _destination_path_ -policy MirrorAllSnapshots -schedule _schedule_`
. 重新同步關係：
`snapmirror resync -destination-path _destination_path_`
. 確認關係狀態和健全狀況：
`snapmirror show`
