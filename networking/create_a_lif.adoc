= 建立 ONTAP 生命
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
儲存設備虛擬機器（SVM）透過一個或多個邏輯介面（LIF）向客戶端提供資料，這些邏輯介面是與實體連接埠或邏輯連接埠關聯的 IP 位址。您必須在要用於存取資料的連接埠上建立 LIF。如果某個元件發生故障，LIF 可以容錯移轉或移轉到不同的實體連接埠，從而繼續與網路通訊。

.開始之前
* 您必須是叢集管理員才能執行此工作。
* 底層實體或邏輯網路連接埠必須處於管理 `up`狀態。


.關於這項工作
您可以在同一個網路連接埠上同時建立IPV4和IPv6 LIF。

.建立具有子網路的 LIFS
* NetApp 建議為資料 SVM 上的所有 LIF 建立子網路物件。這對於 MetroCluster 組態尤其重要，因為子網路物件可讓 ONTAP 決定目的地叢集上的容錯移轉目標，因為每個子網路物件都有一個關聯的廣播網域。如果您規劃使用子網路名稱為 LIF 分配 IP 位址和網路遮罩值，則該子網路必須已存在。如需相關指示，請參閱 link:../networking/create_a_subnet.html["建立子網路"]。
* 處理節點之間叢集內流量的LIF、不應與處理管理流量的LIF或處理資料流量的LIF位於相同的子網路上。
* 建立叢集間網路介面時，無法指定現有子網路範圍內的 IP 位址。
* 從 ONTAP 9.7 開始，當您建立具有子網路的網路介面時，ONTAP 自動從所選子網路中選擇一個可用的 IP 位址並將其指派給該網路介面。如果存在


.各 ONTAP 版本對 LIF 建立功能的支援
與 LIF 建立相關的功能支援因 ONTAP 版本而異。

[cols="2"]
|===
| 從 ONTAP 版本開始 | 功能 


| 9.12.1 | 支援在 System Manager 中為 NFS over RDMA 組態建立網路介面。如需詳細資訊，請參閱 xref:../nfs-rdma/configure-lifs-task.html[透過RDMA設定NFS的LIF]。 


| 9.11.1. | 支援全快閃 SAN 陣列（ASA）系統上的自動 iSCSI LIF 容錯移轉。對於新的 iSCSI LIF ，如果 SVM 沒有現有的 iSCSI LIF ，或所有現有的 iSCSI LIF 都已啟用容錯移轉，則會自動啟用容錯移轉，並採用  `sfo-partner-only` 原則，且自動回復設定為  `true` 。升級至 ONTAP 9.11.1 或更新版本後，如果同一個 SVM 中現有的 iSCSI LIF 未啟用容錯移轉，新的 iSCSI LIF 會繼承  `disabled` 容錯移轉原則。深入瞭解 link:../san-admin/asa-iscsi-lif-fo-task.html["適用於ASA 各種平台的iSCSI LIF容錯移轉"]

| 9.6%  a| 
LIF 使用服務原則來指定其處理的流量類型。在 ONTAP 9.5 及更早版本中，角色用於指定流量類型。

.LIF 建立限制
* 您無法將NAS和SAN傳輸協定指派給相同的LIF。
+
然而，NAS 和基於乙太網路的 SAN 協定可以存在於同一個實體連接埠上。

* 必須為每個支援SAN的儲存虛擬機器（SVM）設定一個LIF處理管理流量。
* NVMe LIF
+
** NVMe傳輸協定必須受到建立LIF的FC介面卡支援。
** NVMe LIF和命名空間必須裝載在同一個節點上。
** 每個 SVM 每個節點最多可設定兩個處理資料流量的 NVMe 生命。
** 資料 LIF 不能在 NVMe 和任何其他協定之間共享。NVMe 資料 LIF 上只能使用 NVMe 協定。
+
深入瞭解 link:../nvme/support-limitations.html["NVMe 組態、支援和限制"]。



* SMB LIF
+
** 如果 SMB 伺服器託管了透過 SMB 搭配 Hyper-V 或 SQL Server 進行不中斷營運的解決方案，請勿將傳輸 SMB 流量的 LIF 設定為自動回復至其主節點。




.步驟
使用 System Manager 或 CLI 建立 LIF。

[role="tabbed-block"]
====
.系統管理員
--
.開始之前
如果您的叢集中有大量 LIF，則可以在建立更多 LIF 之前驗證叢集支援的 LIF 容量。從 ONTAP 9.12.1 開始，您可以在 System Manager 中的「網路介面」網格中檢視處理量。

. 選擇*網路>總覽>網路介面*。
. 選取 image:icon_add.gif["新增圖示"]。
. 選取下列其中一個介面角色：
+
.. 資料
.. 叢集間
.. SVM管理


. 選取傳輸協定：
+
.. SMB/CIFS與NFS
.. iSCSI
.. FC
.. NVMe / FC
.. NVMe / TCP


. 命名LIF或接受先前選擇所產生的名稱。
. 接受主節點、或使用下拉式選單選取一個節點。
. 如果在所選SVM的IPspace中至少設定一個子網路、則會顯示子網路下拉式清單。
+
.. 如果您選取子網路、請從下拉式清單中選擇該子網路。
.. 如果您在沒有子網路的情況下繼續、則會顯示「廣播網域」下拉式清單：
+
... 請指定 IP 位址。如果該 IP 位址已被佔用，則會顯示警告訊息。
... 指定子網路遮罩。




. 從廣播網域中選取主連接埠、可以是自動（建議）或從下拉式功能表中選取一個。主連接埠控制項會根據廣播網域或子網路選擇來顯示。
. 儲存網路介面。

. 在您要用來存取資料的連接埠上建立一個或多個生命體。
+
[source, cli]
----
network interface create -vserver _SVM_name_ -lif _lif_name_ -service-policy _service_policy_name_ -home-node _node_name_ -home-port port_name {-address _IP_address_ - netmask _Netmask_value_ | -subnet-name _subnet_name_} -firewall- policy _policy_ -auto-revert {true|false}
----
+
** `-home-node` 是 LIF 在返回時返回的節點 `network interface revert` 命令會在LIF上執行。
+
您也可以使用-autom-revert選項、指定LIF是否應自動還原為主節點和主連接埠。

+
如link:https://docs.netapp.com/us-en/ontap-cli/network-interface-revert.html["指令參考資料ONTAP"^]需詳細 `network interface revert`資訊，請參閱。

** `-home-port` 是 LIF 在時傳回的實體或邏輯連接埠 `network interface revert` 命令會在LIF上執行。
** 您可以使用  `-address` 和  `-netmask` 選項指定 IP 位址，或者您可以使用  `-subnet_name` 選項啟用從子網路分配。
** 使用子網路提供IP位址和網路遮罩時、如果子網路是使用閘道定義、則使用該子網路建立LIF時、會自動將通往該閘道的預設路由新增至SVM。
** 如果您手動指派IP位址（不使用子網路）、則在不同IP子網路上有用戶端或網域控制器時、可能需要設定通往閘道的預設路由。如link:https://docs.netapp.com/us-en/ontap-cli/network-route-create.html["指令參考資料ONTAP"^]需詳細 `network route create`資訊，請參閱。
** `-auto-revert` 可讓您指定資料 LIF 是否在啟動、管理資料庫狀態變更或建立網路連線等情況下自動還原至其主節點。預設設定為 `false`但您可以將其設定為 `true` 視環境中的網路管理原則而定。
**  `-service-policy` 從 ONTAP 9.5 開始、您可以使用指派 LIF 的服務原則 `-service-policy` 選項。
當為LIF指定服務原則時、該原則會用來建構LIF的預設角色、容錯移轉原則和資料傳輸協定清單。在支援的過程中、服務原則僅適用於叢集間和BGP對等服務。ONTAP在NetApp 9.6中ONTAP 、您可以建立多種資料與管理服務的服務原則。
** `-data-protocol` 可讓您建立支援 FCP 或 NVMe / FC 傳輸協定的 LIF 。建立IP LIF時不需要此選項。

.範例
下列命令會建立 LIF 並使用指定 IP 位址和網路遮罩值 `-address` 和 `-netmask` 參數：

+
....
network interface create -vserver vs1.example.com -lif datalif1 -service-policy default-data-files -home-node node-4 -home-port e1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
+
下列命令會建立LIF、並從指定的子網路（名為client1_sub）指派IP位址和網路遮罩值：

+
....
network interface create -vserver vs3.example.com -lif datalif3 -service-policy default-data-files -home-node node-3 -home-port e1c -subnet-name client1_sub - auto-revert true
....
+
下列命令會建立一個 NVMe / FC LIF 並指定 `nvme-fc` 資料傳輸協定：

+
....
network interface create -vserver vs1.example.com -lif datalif1 -data-protocol nvme-fc -home-node node-4 -home-port 1c -address 192.0.2.145 -netmask 255.255.255.0 -auto-revert true
....
